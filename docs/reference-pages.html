Reference: pages

Every entry in the navigation menu of STX.1 System Monitor v3.0.1. There are 34, verified by counting NavigationViewItem entries in src/SysMonitor.App/MainWindow.xaml. A 35th page, the PDF Editor, is not on the menu: it opens from the EDIT PDF cap on the PDF Tools page (src/SysMonitor.App/Views/PdfToolsPage.xaml:48).

The app defines three group headers (MainWindow.xaml:103, :166, :193). The nine entries above the first header are not under a header of their own, and the five at the bottom are the menu's footer (MainWindow.xaml:211). In the tables, Line is the entry's line in MainWindow.xaml. They are listed in the order the menu shows them.

How a page is laid out

Every page opens on a view header whose stripe reads MOD - <MODULE> - <NN>: the module code in the Module column below, and the page's place in the menu (src/SysMonitor.App/Controls/Instruments/ViewHeader.cs:134). The header carries the page's title and one line of description, and a page's scan and stop caps sit at its right.

Below it, each section is a faceplate whose stripe names it with the module, the section and a letter: CPU - CORE USAGE - 02B is the second section of module 02. Those names are given here and in the other documents so you can point to a section exactly.

Buttons are caps, and their words are written in capitals. A red cap does something that cannot simply be undone, and asks first: the question says what will happen and what cannot be recovered, Enter arms nothing and Escape cancels (src/SysMonitor.App/Controls/Instruments/ConsoleDialog.cs:92-93).

Compression formats

File Tools offers two formats (src/SysMonitor.Core/Services/Utilities/IUtilities.cs:94-98):

  • ZIP, for a file or a whole folder
  • GZip (.gz), for a single file only. This is plain gzip, not a tar archive, so it compresses one file rather than bundling several

7z is not offered. It was removed in v3.0.0 because the code behind it wrote a ZIP and changed the extension, so asking for 7z produced a ZIP named .7z.

Keyboard input

There are no application-wide keyboard shortcuts. The app registers no KeyboardAccelerator anywhere, so no key opens a page or works outside the PDF Editor. Every key the app handles is in the PDF Editor (src/SysMonitor.App/Views/PdfEditorPage.xaml.cs:84-141, :391-398, :1431-1443):

Key Where Action
Ctrl+O Editor Open a PDF
Ctrl+S Editor Save the PDF
Ctrl+P Editor Print
Ctrl+Z Editor, outside a text field Undo
Ctrl+Y Editor, outside a text field Redo
V, P, T, H, R, E, L, A, N, S, X Editor, with a document open, outside a text field Select, Pen, Text, Highlight, Rectangle, Ellipse, Line, Arrow, Sticky Note, Signature and Redact tools (:64-77)
I Editor, with a document open, outside a text field Insert an image
Delete Editor canvas Delete the selected annotation
Esc Editor canvas Clear the current selection
Enter Search box Run the annotation search
Enter Text annotation box Commit the text annotation
Esc Text annotation box Cancel the text annotation

The tool letters are ignored while a text field has the keyboard, where they are the words being typed. The zoom caps' tooltips name -, + and 0, but the editor does not handle those keys; use the caps.

Note that the PDF editor's search looks at annotations, not page text. The app does not extract or search text inside a PDF.
